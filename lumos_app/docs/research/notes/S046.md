# S046 zelinewang/FireSight README
Fetched 2026-10-10 by R4 via WebFetch (HTTP 200, summariser output). Hackathon build.

## Verified facts (README as summarised)
1. "Everything is fetched client-side; there is no server and no API key." Vanilla JS + Leaflet (via unpkg), static hosting on Netlify (`netlify.toml` publishes `src/`, no build step).
2. Feeds: MODIS C6.1 `MODIS_C6_1_Global_24h.csv` and VIIRS NOAA-20 C2 `J1_VIIRS_C2_Global_24h.csv`, from FIRMS's official active-fire file catalog (keyless 24h global CSVs).
3. CORS: README says NASA's CSV responses lack browser CORS headers, so it uses a same-origin `/firms/*` rewrite on Netlify and otherwise falls back to AllOrigins (a third-party CORS proxy) or a direct request; "other static hosts need their own proxy". REPO CLAIM, not tested by us. IMPLICATION: a static PWA that wants a live NRT panel cannot rely on browser-side fetch of FIRMS CSVs on arbitrary hosts. For us (offline-built static JSON) this is moot, but a live panel needs a same-origin rewrite or must be dropped. Recommend we do not use third-party CORS proxies (privacy, availability, terms).
4. Caching: client state in `localStorage`; a backend cache is "roadmap". Limitations say "no persistence or accounts" (internally inconsistent).
5. Dedup: rows "deduplicated within ~1 km" then tiered high/medium/low by brightness and confidence; thresholds not given; unclear whether across sensors.
6. Rate limits: not discussed. Licence MIT.

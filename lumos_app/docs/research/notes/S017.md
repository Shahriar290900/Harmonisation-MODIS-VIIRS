VERIFIED FACTS
1. Title "A global wildfire dataset for the analysis of fire regimes and fire behaviour"; authors Artes T, Oom D, de Rigo D, Durrant TH, Maianti P, Libertà G, San-Miguel-Ayanz J; PMC6884633, PMID 31784525; open access CC BY. First author is Artes (Artés), data-mining MCD64A1 C6 into individual fires; product available through GWIS.
2. Event definition: "a fire event is considered as a set of burnt areas that are connected by touching or intersecting."
3. Temporal split: "Touching burnt areas are considered as different fires if there is a time distance between them of more than 5 days."
4. Clustering: DBSCAN with "the spatial threshold of 0.01 degrees, which is constant for all the globe" (no km conversion given).
5. A fire becomes inactive after 16 days with no new burnt area (could vary by location; published run uses 16).
6. No minimum event area stated; a single patch can form an event. The database stores "the daily burnt areas for each fire". Stats reported "from 2001 to 2017".
7. Limitations stated: pixel quality attributes are lost in vector conversion; thresholds "often require local knowledge or a focus on fire types"; "does not filter by land cover" (agricultural fires kept); differences vs CALFIRE, EFFIS, MTBS attributed partly to differing fire definitions.

CAVEATS: exact numbers (5 days, 16 days, 0.01 degrees) came through a summariser; spot-check against the XML if used as a hard parameter. Resolution and global event count not given in the methods section as relayed.

USE IN PROJECT:
- If we group Lumos hotspots into events, cite this rule as a reference (touching + gap > 5 days splits; 16 days inactive; 0.01 degrees). Note it is for burned-area patches, not hotspots.
- It confirms GlobFire derives from MCD64A1, so it is also MODIS-fire-dependent.

# S031 | FIRMS API tutorial (academy data_api)
URL: https://firms.modaps.eosdis.nasa.gov/content/academy/data_api/firms_api_use.html | fetched 2026-10-10 via WebFetch (summarised by fetch model; quotes as returned) | HTTP: fetched OK

Verified facts:
1. Key limit: key-status output shows "transaction_limit" 5000 over "transaction_interval" 10 minutes. "after 10 minutes, it resets so you can use the system again." (Confirms pack's 5000 / 10 min.)
2. Costs seen in the tutorial: data_availability call "We used 5 transactions."; a one-day WORLD VIIRS area query "We used 36 transactions." So cost grows with area/rows, not a flat 1 per call.
3. Free MAP_KEY required: "we require our users to sign up for a FREE API / map key." Same key also covers WMS, WFS and API calls.
4. Day-range: examples use 1, 3 and 4; the page states NO maximum (the 1-5 vs 1-10 conflict is not settled here; see S027 note).
5. data_id list on the page: MODIS_NRT, MODIS_SP, VIIRS_NOAA20_NRT, VIIRS_NOAA20_SP, VIIRS_NOAA21_NRT, VIIRS_SNPP_NRT, VIIRS_SNPP_SP, LANDSAT_NRT (US/Canada only), GOES_NRT, BA_MODIS, BA_VIIRS. NOTE: no VIIRS_NOAA21_SP is listed here. Availability table has min_date/max_date; "Dates are based on GMT."
6. Country endpoint IS still described: "not recommended for large countries such as USA, China, Canada, Russia" because it "may cause the query to time out." (This contradicts R4's S043 claim that the country endpoint was retired, at least for this tutorial page; the page could be stale. Conclusion: still documented here, not proven working.)
7. Politeness warnings: "a download script with an error could end up requesting too much data"; do not "query our database with high frequency". World VIIRS "can return between 30,000 - 100,000+ records per day."

Caveats: summary came through a small model; the exact day-range maximum and bbox order are not on this page.
USE IN PROJECT: never call the Area API from the browser; any NRT panel should use a prebuilt/cached snapshot or a tiny bbox (Bangladesh, California, NSW) with 1-day range (a world day costs 36 transactions, small bbox far fewer). Prefer country=USA only via bbox, not country endpoint. Key must stay server-side/out of repo.

# S041 abdelrzz9/fireMap README
Fetched 2026-10-10 by R4 via WebFetch (HTTP 200, summariser output).

## Verified facts (README as summarised)
1. "Real-time satellite wildfire monitoring for Algeria": live detections, intensity, history replay, per-wilaya fire risk.
2. Data: FIRMS "VIIRS 375 m + MODIS". Filter: only high-confidence detections kept, with "FRP >= 15 MW", "to filter out noise and small agricultural burns". WARNING for us: this filter would delete most cropland/small-fire activity (Bangladesh), so it is the opposite of what a calendar of burning activity wants; note as an example of silent filtering that the pack says not to do.
3. Endpoints: `GET /fires?days=1..5` (days 1-5 matches the Area API day range in SOURCE_CHECK), `/place`, `/risk`, `/health`.
4. Key handling: needs a free MAP_KEY in server `.env` (`NASA_FIRMS_MAP_KEY`); frontend "Stateless: holds no secrets". Cache: Redis with ETag; no TTL given; rate limits not discussed.
5. Stack: Next.js + MapLibre on Vercel; FastAPI on Railway; no persistence yet (roadmap: PostGIS + Cloudflare R2). Weather: Open-Meteo FWI "the same index EFFIS uses". Licence MIT.

USE IN PROJECT: shows the standard "backend holds MAP_KEY" pattern; our static PWA never ships a key. Nothing to reuse. Do not adopt the FRP >= 15 MW filter.
